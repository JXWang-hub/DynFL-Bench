An executable benchmark for closed-loop FL control

Runtime diagnosis and intervention under hidden composite causes.

DynFL-Bench tests whether a controller can infer hidden, overlapping, and evolving causes from server-visible observations—and select complete, compatible action bundles that remain correct after those actions change the system.

01 / Benchmark

Evaluate the controller, not only the trained model.

Final accuracy entangles decision quality with intervention strength and optimization noise. DynFL-Bench freezes a mechanism-validated cause–action relation and directly audits the controller's decisions at every event and round.

Controller input

Server-visible observations and control context

Controller output

A complete, compatible action bundle

Benchmark-private

Causes, schedules, and event injections

Directly scored

First hit, retention, and restraint

Task

At round t, the agent observes ot = φ(st) and control context mt, then emits Bt = π(ot, mt). A bundle contains at most three actions from distinct families, or no_op alone.

Protocols

Seven atomic causes and nine compatible two-cause cases are complemented by sequential addition, three-cause addition/removal, recurrence, repeated rotation, and a Speech Commands instantiation.

02 / Controller interface

What the agent sees—and what it never sees.

Every LLM receives the same typed, deterministically serialized observation and control context. The scenario, affected clients, event schedule, injections, expected answer, diagnostic rules, thresholds, and frozen cause–action relation remain hidden.

04 / What the trajectories reveal

The controller mistakes suppression for disappearance.

The dominant failure is causal, not syntactic. An intervention removes the visible symptom; the agent then withdraws the intervention, causing the symptom to return.

1Cause creates a symptom
→
2Agent selects the right action
→
3Action suppresses the symptom
→
4Agent withdraws the action
Virtual drift

Qwen repeatedly withdraws moment_align_adapt after apparent recovery despite residual changes in update dynamics.

Real drift

As accuracy recovers, Qwen reattributes the cause and switches from drift_adapt to label-prior correction.

Related failures

The agent adds client selection without new heterogeneity evidence and may reissue completed one-shot concept routing.

Temporal control is not one capability

Addition

Qwen TEH@10 falls from 72.2% before composition to 27.8% after the second cause arrives.

Removal

Selective withdrawal is harder than clearing all actions while preserving the remaining control state.

Recurrence

Correct withdrawal does not imply successful reactivation when the cause returns.

Rotation

Qwen reaches 88.9% of changing states and ends correctly in 77.8%; Composite Rule shows no post-hit regression.

05 / Reproduce

Start with the public contract checks.

The synthetic smoke path and audit checks require no dataset download. Full CIFAR-10 and Speech Commands evaluations are intended for a CUDA-capable environment.

Python 3.12 · Apache-2.0 · test seeds 0, 44, 56

python -m pip install -r requirements.txt
python src/run.py --smoke --synthetic \
  --scenario drift --no_plot --out_dir results/smoke

# Core decision and execution checks
python tests/test_agent_decision_audit.py
python tests/test_b3_phase2.py

# Official random lower bound
python scripts/run_random_bundle_v2.py \
  --suite two-cause --check
python scripts/run_random_bundle_v2.py \
  --suite single-cause --check

# Hidden-cause lifecycle checks
python experiments/lifecycle/b3_lifecycle.py \
  --protocol three_cause --check
python experiments/lifecycle/b3_lifecycle.py \
  --protocol recurrence --check

# Verify paper-aligned result artifacts
python scripts/build_public_results.py --verify
